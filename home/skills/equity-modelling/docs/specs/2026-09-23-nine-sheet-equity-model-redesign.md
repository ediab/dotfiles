## Problem Statement

The current prepared-project runtime builds useful VRT and AVGO proofs, but its varying legacy sheet layouts, quarterly-only rendering, internal metric labels, and unfinished evidence/update checks cannot yet support the agreed company-specific, auditable nine-sheet investment model. In particular, a generic earnings-release selector can silently take one of multiple matches; a full workbook check does not replay frozen facts against the pinned source store; VRT's frozen benchmarks currently contain a dated price but no quantitative guidance/consensus rows. A visually complete workbook must not conceal these gaps or activate unapproved forecasts.

## Solution

Specify one equity-modelling workflow and a fixed **visible sheet order**: **Outlook, Operating Model, Bridge Model, Financial Statements, Valuation, Inputs, Consensus, SourceData, Checks**. The shared runtime owns evidence integrity, period grids, display metadata, sheet layout, keyed references, approval isolation and validation. Each approved company blueprint owns the economic decomposition, available statement lines, formula routes and independent reconciliations. Excel retains editable approved drivers and calculated formulas; Python prepares sources and checks behavior without becoming a parallel financial-calculation engine.

The specification covers the full target, but **trial readiness is not universal validation**. First build the skill/workflow, repair source integrity and prove the shared contracts with small synthetic fixtures and a recalculated sample workbook. Then the user selects the first company and supplies or approves its evidence pack. Propose its blueprint for Gate 1, generate its nine-sheet **historical/inactive-forecast** workbook, inspect it together and revise the skill from the observed result. Real forecasts activate only after Gate 2. Test rollover before claiming update support; a second real company is an optional later generality check, never a prerequisite to the first trial.

## User Stories

1. As an analyst, I want to choose supplied-files-only or pull-data-only evidence for a run and freeze that boundary, so that no other source silently enters my dated investment decision.
2. As an analyst, I want every reported fact traced to an exact source cell and accounting basis, so that I can challenge a disputed number.
3. As an analyst, I want derived periods distinguished from reported values, so that calculated Q4 and annual figures are not misrepresented as issuer disclosures.
4. As an analyst, I want absent and conflicting disclosures explicitly marked, so that missing evidence is not turned into a zero or invented operating driver.
5. As an analyst, I want dated, basis-matched guidance and consensus separated from my own assumptions, so that estimate differences are defensible.
6. As an analyst, I want a proposed company blueprint with checkable examples approved before construction, so that the model reflects that company's economics.
7. As an analyst, I want material quarterly levels beside their appropriate YoY/QoQ views, so that I can see the operating trend behind the thesis.
8. As an analyst, I want an optional compounded two-year comparison where appropriate, so that a distorted one-year comparison does not hide the underlying trend.
9. As an analyst, I want a base-period-to-driver-to-result bridge with independent checks, so that revenue, operating profit and cash changes have a causal explanation.
10. As an analyst, I want clearly separated GAAP and adjusted earnings, EPS and statement lines, so that adjustments do not silently cross accounting bases.
11. As an analyst, I want annual flows, stocks, margins and EPS derived according to their distinct rules, so that annual totals are financially meaningful.
12. As an analyst, I want to edit only identified forecast inputs and approve one complete eight-quarter assumption package, so that proposed or stale values cannot become a live forecast.
13. As an analyst, I want bull/base/bear cases and separately labelled sensitivities, so that I can distinguish a business event from a one-variable stress.
14. As an analyst, I want a dated price-to-enterprise/equity-value build and basis-labelled multiples, so that valuation can be reconciled to the forecast.
15. As an analyst, I want a one-page Outlook with the variant view, expectations gap, catalyst, counterargument and falsifier, so that the model leads to a defensible Long, Short or No Position decision.
16. As a reviewer, I want visible Pass/Fail/Unavailable results and independent numeric reconciliation, so that missing inputs cannot masquerade as a passing check.
17. As a reviewer, I want a recalculated and visually inspected workbook, so that a structurally valid file with broken formulas or unreadable output is not accepted.
18. As an analyst updating after earnings, I want old workbooks and dated forecasts preserved, compatible overrides restored by identity, and estimate changes explained, so that I can learn from the prior call.
19. As a maintainer, I want the user to choose the first trial company and review its generated workbook before broad reuse is claimed, so that feedback improves the workflow without embedding that company's economics in the shared engine.

## Implementation Decisions

### Contracts and ownership

- Keep one skill and two human gates. Gate 1 approves the **user-selected company's** blueprint—reporting/economic segments, drivers and equations, source coverage and gaps, statement scope, benchmarks, valuation, checks, 2–3 concrete examples. Gate 2 separately approves the entire eight-quarter forecast-assumption batch; a proposed, partial, changed, missing-manifest or closed-gate batch activates **nothing**. The first trial may show historical calculations and placeholders while forecasts remain blank. User feedback on layout or economic logic can revise the blueprint before seeking real Gate 2 approval.
- Fix the nine visible sheet names and order. The company module supplies sections, row order, human-readable labels, row formats, formulas and company checks through stable metric/period keys; the shared renderer handles common sheet roles and period/reference mechanics. Preserve internal metric IDs while removing snake_case financial labels. Reuse existing keyed defined-name references; forbid positional cross-sheet links and unexplained numerical hardcodes.
- **Outlook:** one printable page linking the result, key debate, 2–3 causal thesis drivers, house-versus-expectations differences, valuation, coherent bull/base/bear range, catalyst/horizon, counterargument, falsifier and overall Checks status. No duplicate financial hardcodes or forced recommendation.
- **Operating Model:** company-specific regional/segment blocks and detailed revenue-to-profit-to-EPS flow, with level → YoY → QoQ for most meaningful quarterly levels; rates show percentage-point movements. Include gross profit/margin, operating expenses, GAAP and adjusted operating results, non-operating/tax/share lines, incremental adjusted margin, published versus calculated EPS and like-for-like revenue/adjusted-operating-profit/adjusted-EPS benchmarks only when held. Unavailable lines remain visible as gaps, not invented values.
- **Bridge Model:** explicit **same quarter last year** or **previous quarter** base, disclosed or approved drivers, current level and independent tie to a separately sourced reported/consolidated value. The chosen company's blueprint determines the decomposition; VRT's regional and AVGO's segment economics are examples, not templates or required pilots. Never impose Ryanair airline drivers, unsupported price/mix splits or tautological checks; show unexplained residuals or Unavailable.
- **Financial Statements:** separate statement-format income, balance-sheet and cash-flow blocks with common linked totals; GAAP/adjusted bridges use disclosed adjustments. Material working-capital, cash and debt links depend on sourced data or explicitly approved assumptions. If material evidence is missing, surface the sourcing/scope decision and do not claim a complete or balanced three-statement forecast.
- **Valuation:** an available dated price (the selected latest valid close need not be from the most recent row), share count, EV/equity reconciliation, definition- and period-labelled GAAP/adjusted multiples, annual key results, cash returns and scenario outcomes. Distinguish changes in earnings from changes in the applied multiple; keep one-variable sensitivity separate. DCF is optional on blueprint approval, not a default.
- **Inputs:** sole editable forecast-assumption area, exposing readable name plus stable driver ID, unit, basis, period, rationale/source, uncertainty and approval metadata. **Consensus:** read-only estimates with provider, as-of date, explicit fiscal period, unit, analyst count/range when available and known GAAP/adjusted basis; a provider-relative period or unknown basis is context, **not** an asserted like-for-like benchmark, and never feeds the house forecast. **SourceData:** a single canonical entry for each pinned reported input/benchmark plus source and transformation provenance; do not present calculated values as issuer-reported facts. **Checks:** independently grounded company and shared checks with Pass, Fail or Unavailable and an Outlook-linked overall status.

### Evidence and arithmetic

- **Exclusive source mode per run:** choose **supplied-files-only** or **pull-data-only** before inventory. Supplied-files-only uses only the documents the user designates for that run; never query or supplement from the financial-data-pull cache or the network. Pull-data-only uses only the selected pull-store evidence; never supplement from supplied documents. No implicit fallback or mixing. Changing mode or adding evidence creates a new dated frozen pack; prior packs and workbooks remain unchanged. The legacy four-snapshot, provider-only boundary and locator interface must be adapted to express both modes without weakening exact source lineage.
- **Pull-data-only:** inspect held coverage with the pull skill's zero-network index/cache-only route and review its `report` and `absent` results. A held ticker is served as a hash-verified union of snapshots without network calls; confirm with the user **before** a first live pull or explicit refresh, and cap approved requests. Pin the exact source snapshot/table hashes and preserved originals selected from bundle provenance, including when the served union spans runs. The pull's `CHECKED` verdict covers its stated arithmetic and release ties, not model completeness or correctness of every metric. Readable releases and CSV exports are rewritable views, never citation termini.
- **Supplied-files-only:** inventory the chosen folder, hash and preserve the original files, and record issuer, document type, publication/as-of date, fiscal period and exact page/table/cell or passage for each accepted fact. Verify the extracted value and its units/basis against that preserved original; a file hash proves identity, not numeric correctness. Initially support text-searchable PDF, HTML, plain text and Markdown originals. Ambiguous tables, unreadable scans or other unsupported formats produce explicit gaps or a user sourcing decision, not guessed values; OCR/conversion requires a separately reviewable, source-linked result. Transcripts may support qualitative driver reasoning without automatically becoming financial facts.
- The acquisition/freeze step and the prepared-project workbook build remain distinct. The build consumes only the selected, user-approved frozen local pack; live web findings cannot silently become model inputs. Reject a locator that matches multiple eligible cells or a changed/missing hash; never select the first match. A reviewed semantic exception must still be unique.
- Before accepting the freeze/build, replay **every populated pull-store actual and accepted benchmark** from its pinned snapshot/original and declared transforms; for supplied documents, independently verify every populated fact against its exact cited passage or table in the preserved original and retain the review record. In both modes verify identity, value within stated unit/rounding tolerance, period, dimension, basis, hash and dependency chain; an unsupported or unverifiable extraction is Unavailable, not an accepted fact. A missing/ambiguous/mismatched fact fails evidence integrity; an honestly unavailable, reasoned fact remains Unavailable. Detect a modified raw payload, stale derived view and altered frozen value. Report coverage counts for replay and document verification separately, not merely presence of lineage text. Existing frozen projects must be migrated or explicitly re-frozen against this rule, never grandfathered in as verified.
- Separate normalization (scale, sign, dimensional selection) from arithmetic derivation. Preserve provenance for both; source-level reported values enter once, while Q4 from FY minus nine months, YTD deaccumulation, aggregate levels, growth, margins and annual results have visible Excel formulas referring to the reported operands. If the present canonical evidence rows contain precomputed derivatives, retain their provenance for audit but **do not hardcode them in the new workbook as reported values**. A new evidence representation may be needed; its outward contract is reproducible operands, exact source lineage and explicit reported/derived status rather than a prescribed schema shape.
- Use the company's fiscal-quarter keys and declared fiscal-end dates, including non-calendar 52/53-week years where applicable. YoY uses the same fiscal quarter a year earlier; QoQ the prior fiscal quarter; annual YoY compares fiscal years, with no annual QoQ. Optional two-year stack is current divided by the same fiscal period two years earlier minus one, not summed growth rates. Missing, zero or economically misleading baselines produce a blank and an explanatory unavailable status, not 0%.
- Annual flow is the sum of all four available quarters; annual balance is fiscal-year-end stock; annual margins and EPS are recomputed from annual numerator/denominator and the stated share convention, not summed quarterly ratios or EPS. Distinguish absolute percentage-point margin change from incremental adjusted operating margin, which is change in adjusted operating profit divided by change in revenue. Normalize percentage-unit conventions before applying display formats or formulas.
- A dated consensus or guidance series must identify the same fiscal period, metric definition, unit, as-of date and accounting basis as the compared house result. Provider-relative estimate labels (e.g. `0q`/`0y`) require a verified fiscal-period mapping; unknown GAAP/adjusted basis stays unknown. Missing revenue, adjusted operating profit or adjusted EPS benchmarks remain blank/Unavailable until named, comparable values are selected from the run's approved sources. Estimates are **supporting evidence, not a prerequisite** to building a historical model or proposing/approving forecast drivers; an unavailable comparison cannot be claimed as a consensus variance. A valid dated closing price is sufficient for a price-based valuation even if a later row is blank. Material operating or accounting gaps require an explicit sourcing/scope decision before claiming decision readiness; a missing optional consensus comparison alone does not block the company trial or force No Position.

### Updates and release

- The update branch creates fresh frozen evidence and a newly named workbook, preserves old source packs/workbooks byte-for-byte and retains the **prior dated forecast** for forecast-versus-actual comparison. Carry user overrides only by matching driver ID, fiscal period, unit and definition; carry designated Outlook text by field identity, including deliberate blanks. List rejected/retired overrides, restatements, changes in sources, reported-versus-forecast differences and the revenue/earnings/cash/valuation estimate-change bridge.
- Material changes to segments, equations, statement depth, scenarios or valuation reopen Gate 1; every new or materially changed forecast quarter reopens Gate 2. Keep old and new values visible for the earnings review without making a stale approval live.
- Align executable skill, workbook rules, artifact contracts, update guide, runtime and installed copy only after verified behavior exists. Archive files remain historical. A historical note or passing unit test is not a substitute for an implemented release check.

2. **User-selected company and Gate 1.** The user chooses the company, selects one source mode and approves its frozen evidence boundary. 3. **First real workbook and feedback.** Build exactly nine sheets for the chosen company from its frozen pack: reconciled history, readable labels, derived annuals and a company-specific bridge. Show the eight-quarter horizon but leave unapproved forecast outputs blank. Recalculate, inspect/render every sheet and check Outlook printing. Show the user the workbook; revise the skill or blueprint from concrete feedback in a new dated delivery, preserving previous artifacts.
4. **Forecast approval and update support.** Present Gate 2 assumptions only when the user wants to activate the first real forecast. Approval must cover the complete eight-quarter dependency set; fixture-only approval never activates the real delivery. Verify forecast propagation and scenario/sensitivity behavior. Prove rollover on a representative prior/new project, including preserved artifacts and forecast-versus-actual/estimate-change explanations, **before calling the update workflow validated**; a real subsequent earnings update provides stronger proof when available.
5. **Optional generality check.** A later user-selected second company can test whether shared roles hold across different segments, fiscal calendars and percentage conventions without issuer-named branches in the shared engine. Record its gaps and revise the workflow as needed. A second real company is useful evidence for broad reuse, **not a gate to the first company's trial**.

## Acceptance Criteria and Concrete Success Examples

- **Evidence:** 100% of populated frozen actuals and accepted benchmarks in either mode replay or are independently verified against the exact immutable original and recorded transforms; no ambiguous selector, changed payload or uncertified manual extraction passes. A supplied-files-only run never consults the pull store, even if that ticker is cached; a pull-data-only run never reads supplied files. Missing, unsupported or ill-defined figures are explicitly Unavailable, never silently zero or chosen by position. The evidence report names the offending metric, period and source on failure.
- **Workbook:** exactly the nine sheets in the stated order, with human-readable row labels and keyed references; appropriate quarterly level/YoY/QoQ blocks, optional two-year stack, annual periods and no unsupported hardcodes. Calculated values remain formula-derived and blank propagation is verified. A missing component cannot yield Pass for an accounting identity.
- **Gates and decisions:** without complete valid Gate 2 approval, all forecast outputs stay inactive. In a synthetic approved fixture, changing a company-owned growth driver changes revenue, operating profit, EPS, cash and valuation via formulas while historical facts and benchmarks do not move. Check the chosen company's approved driver against every supported link too; if a material cash link is unavailable, mark that dependency Unavailable rather than claiming the full propagation criterion passed.
- **Recalculation and readability:** no unexplained formula errors, stale/missing calculation results on decision-driving formulas, broken defined names or positional cross-sheet formulas; independent segment/earnings/cash/valuation checks report accurate Pass/Fail/Unavailable, and all nine rendered sheets plus the printable Outlook are reviewed.
- **Readiness claims:** fixture/recalculation checks plus evidence integrity make the skill **ready for a company trial**. A sourced, recalculated, reviewed first workbook establishes fit only for that chosen company and stated scope. Update support is validated only after a representative rollover preserves old artifact hashes and prior forecasts, carries compatible overrides and narrative, and lists estimate changes and withheld values. Broad cross-company claims require a later second-company proof; neither VRT nor AVGO is mandatory. Skill documentation and the installed copy must match the tested runtime.

Three proposed examples for the user to confirm or edit before implementation/review:

1. In a pinned synthetic source fixture, same-quarter revenue of **100** followed by **125** produces **25% Revenue YoY** in the Operating Model, linked to those source periods. Remove either comparable: the growth cell becomes blank, not zero. The user's chosen company supplies its own sourced numeric example at Gate 1.
2. For the **same fiscal quarter** in three successive years at 100, 110 and 132 units, the optional two-year stack is **32%**, not 10% + 20% = 30%; margins instead display percentage-point changes and no default two-year stack.
3. If two cells of the same pinned 8-K release match a requested adjusted result, freezing/replaying that fact **fails with an ambiguity identifying the period and candidates**; no workbook may silently use the first cell. A modified raw exhibit or changed frozen amount also fails source replay.

## Testing Decisions

- Test externally observable contracts, not renderer coordinates or implementation-specific helper names. Prefer the existing **prepared-project freeze → build/check** seam and the **recalculated `.xlsx` inspection** seam: each asserts whole-project evidence, gate, sheet and financial outcomes. Add small resolver tests for ambiguity, provenance tampering and transform replay because a workbook-only test cannot localize those failures. Use the existing CLI, engine, evidence, checks and rollover contract tests as prior art; company identity tests remain company-owned.
- Use isolated synthetic fixtures and fresh dated outputs; never overwrite existing prepared projects, including VRT/AVGO artifacts. Test both source modes with an irrelevant cached ticker beside supplied files, a missing local fact, a modified preserved document and a served multi-snapshot pull union; neither mode may read the other's sources or use a derived export as an original. Independently compare sourced reported totals, derived cash/EPS and published comparables; do not validate a formula against itself. Inspect both formula text and recalculated values, plus all nine rendered sheets and Outlook print area. Test closed/proposed/partial/stale approvals, unsuitable growth bases, differing percentage scales, non-calendar fiscal dates, optional/mismatched estimates, a blank latest price row and every Checks status. A suite pass without Excel recalculation is insufficient.
- Keep a focused test proving an approved input affects revenue → profit → EPS → cash → valuation and not actuals/benchmarks. Separately exercise a cohesive scenario and a single-variable sensitivity. Test one full rollover with prior/new project hashes, override/text identity, new-quarter gate reset and estimate-change reconciliation.
- **Test-seam confirmation:** these are the build/check and recalculated-workbook seams explicitly requested in the original prompt; the three proposed numerical/failure examples above become binding acceptance examples once the user confirms or edits the spec.

## Out of Scope

- Implementing code, modifying the executable skill or constructing a workbook **during this spec step**; further work requires explicit approval.
- A generic sector template, airline-driver transplant, formula DSL, second independent Python financial engine, mandatory DCF or extra workbook tabs.
- Automatic live acquisition during workbook construction, mixing source modes, using uncaptured web research as a model fact, inventing consensus or price/volume splits, treating an illustrative Ryanair number as VRT/AVGO evidence, or forcing a Long/Short call when No Position is warranted.
- Mandating VRT, AVGO or any second-company workbook before the user can trial a chosen company. Do not claim a complete three-statement model or universally available earnings consensus where primary evidence or comparable dated benchmarks are missing; a visibly limited partial output is not broad validation.
